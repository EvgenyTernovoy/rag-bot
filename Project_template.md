| Критерий                   | Облачные модели (OpenAI / YandexGPT)                                 | Локальные модели (Hugging Face)                         |
|----------------------------|------------------------------------------------------------------------|---------------------------------------------------------------------------|
| **Качество ответов**       | Высокое out-of-the-box; модели регулярно обновляются и улучшатся     | Хорошее, особенно после дообучения; может уступать в нюансах и стабильности |

### Конфигурация сервера

Элементы системы:
- RAG - поиск релевантных документов через эмбеддинги + векторное хранилище
- LLM - формирует ответ на основе найденных фрагментов

Требования:
- хранение и быстрый поиск эмбеддингов (≈ 20–30 тыс. документов/страниц);
- периодическое обновление индекса (400 новых страниц/мес);
- инференс LLM (генерация ответа);
- возможность масштабирования (по пользователям и нагрузке).

Сравним 3 варианта:
- локальный сервер (для небольшого колличества пользователей)
- гибридный, LLM в облаке; эмбеддинги и поиск локально
- локальный кластер

| Параметр                     | Локальный сервер | Гибрид (LLM в облаке) | Кластер (масштабный) |
|------------------------------|------------------|------------------------|----------------------|
| CPU                         | 16 ядер          | 8 ядер                 | 16–32 ядер × неск. узлов |
| RAM                         | 64 ГБ            | 32 ГБ                  | 64–128 ГБ на узел     |
| GPU                         | RTX 4090 / A100  | –                      | 2×A100 или H100       |
| Хранилище (SSD/NVMe)        | 2 ТБ             | 1 ТБ                   | ≥ 4 ТБ на кластер     |
| Векторная БД                | FAISS / Qdrant   | FAISS / ChromaDB       | Qdrant (кластер)      |
| Эмбеддинги                  | локально         | облако (OpenAI)        | локально + batch GPU  |
| LLM                         | локально (7B–8B) | облачно (GPT-4/5)      | локально (70B)        |
| Пользователи (параллельно)  | до 15            | до 30                  | 100+                 |
| Стоимость (CapEx / OpEx)    | ~ $6–8 тыс. единоразово | ~$100 / мес API + 50$ сервер | от $15–25 тыс. кластер |

#### Ключевые требования

| Фактор             | Значение для компании                                    |
| ------------------ | -------------------------------------------------------- |
| Конфиденциальность | Критично — часть документации нельзя отправлять в облако |
| Объём данных       | Средний (до 25–30 тыс. документов)                       |
| Рост данных        | ~400 страниц / мес — требует масштабируемости            |
| Пользователи       | Разработчики, саппорт, менеджеры, новые сотрудники       |
| Задачи             | Поиск, суммаризация, Q&A по документации                 |

#### Варианты архитектуры

##### Вариант 1 — Полностью облачный (OpenAI / YandexGPT)

Вся обработка (эмбеддинги, поиск, LLM-инференс) происходит в облаке. Документы выгружаются и индексируются в внешнем сервисе (например, Pinecone, Weaviate Cloud, OpenAI + LangChain).

| Параметр            | Описание                                             |
| ------------------- | ---------------------------------------------------- |
| Эмбеддинги          | OpenAI text-embedding-3-large / YandexGPT Embeddings |
| Векторное хранилище | Pinecone / Weaviate Cloud                            |
| LLM                 | GPT-4 / YandexGPT Pro                                |
| Хостинг             | Облачный (SaaS)                                      |

Плюсы:
- Максимально простое внедрение (дни, не недели).
- Высокое качество ответов и скорость.
- Не требует собственной инфраструктуры.

Минусы:
- Конфиденциальные данные не могут быть загружены.
- Стоимость растёт пропорционально количеству запросов.

Подходит для публичной и внешней документации.

##### Вариант 2 — Полностью локальный (on-premise)

Все данные, эмбеддинги, поиск и генерация находятся в инфраструктуре компании.

| Компонент           | Инструмент                                                     |
| ------------------- | -------------------------------------------------------------- |
| Эмбеддинги          | Sentence-Transformers (`all-mpnet-base-v2`, `e5-base`)         |
| Векторное хранилище | FAISS / Qdrant (on-prem)                                       |
| LLM                 | Llama 3 8B / Mixtral 8×7B / Mistral 7B (через vLLM или Ollama) |
| Фреймворк RAG       | LangChain / LlamaIndex                                         |
| Хостинг             | Внутренний сервер / Kubernetes-кластер                         |

Плюсы:
- Полный контроль над данными.
- Можно fine-tune модели под корпоративный язык.
- Не зависит от внешних API.

Минусы:
- Высокие требования к GPU и RAM.
- Настройка и обслуживание сложнее.
- Обновления моделей придётся делать вручную.

**Рекомендуемая инфраструктура**
| Ресурс    | Конфигурация                |
| --------- | --------------------------- |
| CPU       | 32 vCPU                     |
| RAM       | 128 GB                      |
| GPU       | 1 × NVIDIA A100 / RTX A6000 |
| Хранилище | 2 TB NVMe                   |

Подходит при строгих требованиях безопасности

##### Вариант 3 — Гибридный (локальный индекс + облачный LLM)

Конфиденциальные данные хранятся и индексируются локально.
Облачные модели используются только для обработки «чистых» запросов и для reasoning-части.

| Компонент              | Инструмент                                                    |
| ---------------------- | ------------------------------------------------------------- |
| Эмбеддинги             | Sentence-Transformers (локально)                              |
| Векторное хранилище    | FAISS / Qdrant                                                |
| LLM (по маршрутизации) | OpenAI GPT-4 / YandexGPT Pro (внешний) + Llama 3 (внутренний) |
| Оркестратор            | LangChain / LlamaIndex + middleware-роутер                    |
| Хостинг                | VPS или on-prem сервер + облачный inference                   |


Плюсы:
- Конфиденциальные данные остаются внутри компании.
- Стоимость ниже, чем у полностью локальной схемы.
- Гибкость в использовании моделей (по чувствительности).
- Простое масштабирование при росте данных.

Минусы:
- Более сложная настройка маршрутизации.
- Нужна система классификации документов (внутренние / внешние).

**Рекомендуемая инфраструктура**
| Ресурс    | Конфигурация                                   |
| --------- | ---------------------------------------------- |
| CPU       | 16 vCPU                                        |
| RAM       | 64 GB                                          |
| GPU       | Не требуется (при облачном inference)          |
| Хранилище | 1 TB SSD                                       |

Лучший баланс между безопасностью, качеством и стоимостью.


##### Вариант 4 — Облако с приватным контуром (VPC / PrivateLink)

Всё развёрнуто в закрытом облаке (например, Yandex Cloud VPC, AWS PrivateLink).
Данные не покидают приватную сеть, но вычисления масштабируются в облаке.

Плюсы:
- Безопасность близкая к on-prem.
- Масштабируемость и SLA облака.
- Быстрая настройка при наличии корпоративного контракта.

Минусы:
- Привязка к конкретному облаку и тарифам.
- Возможны дополнительные расходы на приватный трафик.

#### Решение

Оптимальным выбором для нашей компании является гибридная архитектура:

- локальные индексы и документы (FAISS / Qdrant + Sentence-Transformers);
- маршрутизация запросов между локальной Llama 3 и облачным GPT-4 / YandexGPT;
- оркестрация через LangChain / LlamaIndex;

Такое решение:
- обеспечивает безопасность конфиденциальных данных
- даёт высокое качество поиска и ответов
- остаётся стоимостно эффективным и масштабируемым
